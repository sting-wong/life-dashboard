## 1. 产品定位

**产品名：个人行动与创作系统**

不是单纯笔记工具，不是单纯任务工具。核心解决五类真实需求：

| 需求 | 解决方案 |
|---|---|
| 学习 / 工作任务太多，需要梳理 | Tasks + Workspace |
| 每天需要固定专注时间执行 | 首页今日执行视图 |
| 日常看到的内容需要收藏整理 | Inbox |
| 自媒体运营面板（内容整理 + 数据复盘） | Creator |
| 安全保存 API key、账号密码等敏感信息 | Vault |

**产品主线（信息流向）：**

```
Inbox 收集灵感
  → Workspace 整理和创作
    → Tasks 拆成行动
      → 首页今天执行
        → Creator / Analytics 复盘结果
Vault 独立管理敏感信息（独立于主线，不参与流转）
```

## 2. 一级板块

### 2.1 首页 / 控制面板

**职责（只做这些）：**
- 今天我该做什么
- 当前时间块 / 当前专注
- 今日习惯
- 本周任务摘要
- 目标进度摘要
- 数据摘要
- 快速入口（进入其他板块）

**不做：**
- 不放大量收藏内容
- 不放长篇编辑器
- 不做复杂内容整理

**UI 参考：**
- Todoist：执行感、高密度可扫读的任务列表
- 12 Weeks Year：目标感、周期感

---

### 2.2 Workspace / Free Studio（v0.2）

**职责（只做这些）：**
- 自由写作，打开即写
- 周计划整理
- 内容创意整理
- Slash 插入式内容块组织
- 把想法慢慢变成任务、内容或计划

**不做：**
- 不做收藏中心（收藏由 Inbox 负责）
- 不做密钥管理
- 不做完整数据分析
- 不再采用"一个个框起来的 Section 富文本卡片"作为核心体验

**目标体验：**  
打开后可以直接写。需要结构时输入 `/` 插入内容块。

**Slash 菜单规划：**

第一批（MVP）：
- Todo 清单
- 本周计划
- 内容创意
- 标题 / 字号大小

第二批（轻量版）：
- 链接收藏：先支持 URL 卡片，不做复杂预览
- 简单表格：先做基础表格，不做数据库级表格
- 收藏图片：先支持图片 URL / 图片卡片，不做上传系统

**UI 方向（A + B 结合）：**
- A：Notion 空白页的自由输入
- B：今日自由工作台的轻引导和美感

**与 Inbox 的边界：**
- Workspace 可轻量引用 Inbox 素材（例如拖入一张收藏卡片）
- Workspace 不承担原始收集功能

---

### 2.3 Inbox / 灵感收藏

**职责（只做这些）：**
- 看到的内容先收进来（文章、图片、视频、链接、选题灵感）
- 统一收集，支持稍后整理
- 后续可转内容创意、转任务、引用到 Workspace

**不做：**
- 不在 Inbox 深度创作
- 不承担 Workspace 的自由写作功能
- 不做自媒体数据复盘

**UI 参考：**
- Blinkist：内容卡片、标题 + 摘要 + 标签
- Readwise Reader：内容流、稍后整理体验

---

### 2.4 Creator / 自媒体运营

**职责（只做这些）：**
- 内容选题库
- 内容日历
- 发布状态跟踪
- 平台数据（播放、点赞、收藏、评论、涨粉等指标）
- 单条内容复盘
- "下一条内容做什么"+ "上一条内容表现如何" 双视角

**不做：**
- 不做普通任务管理
- 不做灵感原始收集
- 不做自由笔记编辑器

**UI 方向：**
- 数据面板 + 内容生产面板结合
- 不是单纯 analytics 图表
- 要能同时看到内容计划和历史数据

---

### 2.5 Vault / 密钥账号

**职责（只做这些）：**
- API key
- 账号密码
- 服务名称 + 备注
- 搜索 / 复制 / 隐藏与显示
- 安全提醒

**不做：**
- 不混入 Workspace 或普通笔记
- 不在首页展示明文
- 不和 notes 混在一起

**安全要求：**
- 首页只放 Vault 入口，不查询、不展示任何 key 明文
- 只有用户进入 Vault 并主动操作，才显示明文
- 敏感信息独立存储，不参与其他板块的数据流

## 3. 视觉方向

### 关键词

少边框 · 更自由 · 温暖纸感 · 强留白 · 柔和卡片  
不像后台表格 · 不像框起来的富文本 · 有产品感 · 有动效空间（第一版不重动效）

### 整体气质

| 目标 | 避免 |
|---|---|
| 温暖、轻、清晰 | 冷硬、信息密度过高 |
| 有秩序但不压迫 | 企业后台感 |
| 像个人工作室 | 像 SaaS 管理系统 |

### 颜色方向

| 角色 | 颜色 |
|---|---|
| 背景 | 米白 / 纸感（非纯白） |
| 主色 | 深绿（现有 #1A7A4A） |
| 强调辅助 | 琥珀色 |
| 分类辅助 | 柔和蓝 / 玫瑰色 |
| 禁止 | 大面积高饱和色 |

## 4. 参考来源与适用范围

| 参考产品 | 借鉴要点 | 适用板块 |
|---|---|---|
| 12 Weeks Year (Notion) | 12 周目标、本周目标、每日执行、周复盘、目标进度 | 首页、Workspace、Creator 复盘 |
| Todoist | 快速任务输入、今日/本周任务、checkbox 执行感、高密度可扫读列表 | 首页、Tasks、Workspace Todo block |
| Blinkist | 内容卡片、阅读收藏内容流、标题+摘要+标签、稍后整理 | Inbox、Workspace 素材引用、Creator 内容卡片 |
| Notion | Slash 插入、自由编辑、模板插入、块级内容组织 | Workspace / Free Studio |

## 5. 页面边界原则

**旧问题：** 每个页面都想解决所有事情，用户不知道该在哪里做什么。

**新原则（每个板块只做一件事）：**

| 板块 | 唯一职责 |
|---|---|
| 首页 | 今天执行 |
| Workspace | 自由整理和创作 |
| Inbox | 原始收集 |
| Creator | 内容生产与复盘 |
| Vault | 敏感信息管理 |

**跨板块流转只走单向：**  
Inbox → Workspace → Tasks → 首页  
不允许反向混入（例如 Workspace 不变成收藏中心）

## 6. 实施范围说明

本 spec 描述整个 Product UI System v1 的产品定位和设计方向，不是一次性实现所有板块。

**当前已有实现：**
- 首页（已升级为行动驾驶舱结构）
- Workspace v0.1（Section 卡片式，已确认需升级）
- Tasks / Habits / Schedule / Goals / Notes / Vault（API Keys）

**v1 系统改造重点（按优先级排序，具体计划在 Plan 阶段拆解）：**
1. Workspace v0.2 — Free Studio（最高优先级，当前体验落差最大）
2. Inbox — 新板块，从零开始
3. Creator — 新板块，从零开始
4. 视觉系统统一 — 米白背景、少边框、柔和卡片（可以随板块改造逐步落地）

**本 spec 不覆盖：**
- 具体数据库 schema 设计
- 路由文件列表
- 组件拆分方案
- 上述内容在 Plan 阶段输出
